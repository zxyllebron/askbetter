# AskBetter 1.0

## Windows 按钮助手

解压后双击 `AskBetter.exe`。无需 Node、Python 或额外 API Key；需要 Windows 10/11、.NET Framework 4.8、已安装并登录的 Codex CLI、网络连接以及所选模型/Fast 的使用权限。找不到 CLI 时可在 `settings.json` 的 `codexPath` 填写本机可执行文件的绝对路径。

首次启动从 `settings.example.json` 生成本机 `settings.json`，默认适中、圆钮模式。本机配置不应上传 GitHub。公开仓库的构建、测试、打包及许可证见根目录 README.md 和 LICENSE。

1. 默认启动后切回 Codex，助手自动识别当前输入框；需要重新指定时，可点击输入框并按 **Ctrl+Alt+B** 绑定。若上次选择了单独对话框模式，重启会恢复该模式。
2. 26×26 逻辑像素圆钮使用 16×16 魔棒图标，定位在输入框底栏、模型选择器左侧，间距 8 逻辑像素。它是透明独立窗口上的圆钮，不修改 Codex 安装文件。
3. 在 ChatGPT/Codex 中，仅点击圆钮触发优化；完成后替换已绑定输入框内容，不按回车、不发送。
4. 按 Ctrl+Alt+Z 恢复上次原稿。
5. 后台优化期间草稿、输入框身份或窗口标题改变时停止覆盖，结果保留在手动面板。
6. 右键菜单仅包含下述 5 项。按 Ctrl+Alt+Q 退出助手。

## 右键菜单与模式

1. **简短**：删除冗余、合并相近要求，用自然短句简洁直接地表达。
2. **适中**：识别当前任务、最终目标及必要条件，重组逻辑，兼顾完整与效率。
3. **详细**：区分背景、任务、步骤、目标和约束，复杂任务分点；不新增任务或编造信息，简单任务不刻意扩写。
4. **单独对话框模式**：从圆钮切换到独立输入、输出对话框。对话框内右键菜单及“设置”也有相同 5 项，第 4 项为 **初始模式**，点击后回到圆钮。
5. **更改模型**：选择本机 Codex 返回的模型或手动输入模型标识，点保存后用于下一次优化。

选择前三项只切换长度档位，不立即提交草稿，也不改变模型。之后点击圆钮或对话框里的“优化”；单独对话框也支持 Enter 优化、Shift+Enter 换行，中文输入法确认候选文字不会触发优化。当前档位以勾选标记显示，两种界面共享长度和模型；长度、模型及界面模式会保存在 `settings.json`，重启后恢复。

单独对话框保留“优化”和“设置”，不显示“复制结果”按钮及底部说明。选中输出文本按 Ctrl+C 复制。关闭窗口会返回初始模式；独立对话框的结果不会自动写入 Codex。初始模式仍直接优化、回填当前 Codex 草稿，不自动发送。

按钮跟随模型选择器坐标，而非固定屏幕坐标。缩放页面或调整窗口大小时临时隐藏；布局稳定约 300 毫秒后重新定位并显示，缩放过程中不追赶位置。空间不足不会主动隐藏。切到其他应用、输入框离屏或无法识别模型控件时不显示，避免将按钮放在错误窗口上。切换聊天会重新识别输入框。

单按 Ctrl 或使用 Ctrl+A/C/V/Z 等编辑快捷键不会隐藏圆钮。只有实际的 Ctrl 加减号、Ctrl+0、Ctrl+滚轮缩放及窗口大小变化才触发缩放隐藏。按模型选择器附近的可编辑区域识别输入框，不要求固定的占位文字；“Do anything”和“Work with Codex”等不同聊天均可识别。点击切换聊天、切换窗口或发现旧控件失效时自动重新定位，无需逐个聊天手动绑定。

当前模型设置：`gpt-6-luna` / `low` / `fast`。可通过“更改模型”修改，长度切换不改变它。仅影响优化助手，不改变主聊天模型。Fast 会消耗对应加速额度。助手在后台直接复用本机 Codex 登录；每次创建独立的临时优化会话，避免旧提示词串入新任务。

## 优化指令与程序逻辑

三档各自使用完整优化指令，不再通过替换一句长度描述生成。指令文件为：简短 `optimizer-prompt-brief.txt`、适中 `optimizer-prompt.txt`、详细 `optimizer-prompt-detailed.txt`。可用记事本分别编辑，保存为 UTF-8，退出并重启助手后生效。通过菜单切换长度或模型立即生效并保存；手动修改 `settings.json` 需要重启。独立调用 `$askbetter` 时使用 `SKILL.md`，读取对应模式文件。

程序不设置固定输出字数上限，不额外追加长度偏好。每次请求按当前档位使用对应文件的完整内容。三档均只改写、不执行任务，仅返回 JSON 对象，prompt 字段为优化后的提示词。JSON 格式用于程序提取结果，不会回填到草稿中。

1. 绑定输入框时，记录 Windows 控件身份、所属窗口和窗口标题。
2. 缓存已识别的输入框和模型选择器，在稳定状态下读取坐标。原生移动/缩放事件与轻量窗口尺寸检测会立即隐藏圆钮，并丢弃旧定位任务；结束缩放后再一次定位显示。
3. 点击圆钮后读取输入框纯文本，并记录原稿快照。本次只处理这段草稿；不收集整段聊天记录，不读取附件。
4. 通过 Codex app-server 复用本机登录，创建独立临时会话。当前模式的完整优化指令作为 baseInstructions 和 developerInstructions 发送；草稿单独以 `{"draft":"输入框原文"}` 发送。
5. 使用当前保存的模型（默认 `gpt-6-luna`）、推理 `low`、速度 `fast`，要求返回 JSON：`{"prompt":"优化后的提示词"}`。JSON 外壳用于准确提取结果，不会写进输入框。
6. 等待最终回复，忽略中间说明；验证结果非空。超时、失败或不接受指定模型/速度时保留草稿，不以错误文本覆盖。
7. 回填前重新检查控件身份、窗口标题和草稿内容。发生变化时不覆盖，将结果留在手动面板。
8. 校验通过时，通过可编辑接口直接替换；没有可编辑接口但可读时，聚焦输入框，再次校验后用 Ctrl+A、Ctrl+V 回填并尽量恢复剪贴板。不按 Enter。
9. 保存本次原稿供撤销。撤销前也检查当前文本是否仍是该次优化结果，避免抹掉后续编辑。

此程序不依靠把消息发到另一个可见 Codex 窗口再复制回复。后台直接调用独立临时会话，因此无需常开第二个窗口。首次优化会启动后台进程，后续复用该进程，但每次草稿使用独立临时会话。

## 兼容性边界

直接回填依赖 Windows UI Automation。某些 Codex 版本不提供输入框文本或模型按钮名称，绑定/定位可能失败。需要按该版本适配，不能把手动复制模式当作直接回填已完成。手动面板可独立优化并复制结果。

对不支持 ValuePattern 的富文本输入框，会在再次确认草稿及焦点后使用 Ctrl+A、Ctrl+V，并尽量恢复剪贴板。附件不在优化范围内；粘贴路径是否保留附件、撤销历史及富文本结构，需要在目标客户端验证。光标位置不会保留。

模型输出可能改变措辞，发送前请检查关键限制。失败或超时不以错误文本覆盖草稿。输入与结果仅保留在助手内存中；Codex 服务仍按其账户规则处理请求。软件不会复制登录凭据进入压缩包。

## 单独使用 skill

将整个 `askbetter` 文件夹放入项目 `.agents/skills/` 或个人 `~/.agents/skills/` 目录，或运行 `install-skill.ps1`。然后在 Codex 调用 `$askbetter` 并提供待优化内容。若本机版本使用其他技能目录，请使用客户端实际识别的目录。

skill 改写规则可移植至其他支持 Agent Skills 的环境；Windows 按钮程序不适用于 macOS、Linux、网页或 IDE。任意目录解压不会自动注册 skill。skill 本身不能强制当前聊天切换模型，模型配置由助手负责。

## 开发和诊断

`build.ps1` 从附带 C# 源码重编译，无第三方库。

`AskBetter.exe --optimize-file input.txt output.json` 可验证模型连接和改写结果，不读取或改动桌面输入框。

快捷键：Ctrl+Alt+B 绑定、Ctrl+Alt+Z 撤销、Ctrl+Alt+Q 退出。原对话输入框只点击圆钮优化；单独对话框也支持 Enter 优化、Shift+Enter 换行。
